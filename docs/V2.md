# v2 — Todo desde la interfaz gráfica

Objetivo: nadie abre una terminal ni edita un archivo. Hay tres superficies, todas con la
misma interfaz web y el mismo binario de Go:

| Superficie | Ruta | Quién | Qué |
|---|---|---|---|
| Tele (kiosco) | `/` | cualquiera en la red | Solo ver. Sin cambios respecto a v1 |
| Panel de administración | `/admin` | el instalador, con contraseña | Sucursales, cámaras, estado, reiniciar DVR, ajustes, Telegram, vínculos |
| Asistente de instalación | `/instalar` | la app de escritorio en la laptop | Buscar DVR en la red de la sucursal, probar, vista previa, enviar a la central |

El asistente corre en la **laptop** (app de escritorio, modo `instalador`). El panel corre en la
**PC central** (modo `central`, el `monitor run` de siempre). El asistente envía las sucursales
a la central por Tailscale con un **token de vínculo** que se genera en el panel.

Este documento complementa `docs/ARQUITECTURA.md`; lo que no se menciona aquí no cambia.

## Paquetes nuevos y dueños

| Paquete | Qué | Trabajador |
|---|---|---|
| `internal/dvr` | API de cada marca: identificar, foto, reiniciar | A |
| `internal/descubrir` | Barrido de red sin credenciales | A |
| `cmd/dvrfalso` | DVR simulado (Hikvision ISAPI, Dahua CGI, ONVIF) para desarrollo y pruebas | A |
| `internal/almacen` | Sucursales, ajustes y admin persistidos; recarga en caliente | B |
| `internal/servidor` (ampliar) | API de admin, API del instalador, sesiones | B |
| `internal/salud`, `internal/go2rtc`, `cmd/monitor` (ampliar) | recarga en caliente, recuperación por huella, modo instalador | B |
| `web/src` | panel `/admin` y asistente `/instalar` | C |

Las firmas públicas de `internal/dvr/dvr.go` y `internal/descubrir/descubrir.go` son el
contrato entre A y B. A puede convertir las variables `Nuevo`, `Buscar` y `RedesLocales` en
funciones normales (el llamado `dvr.Nuevo(d)` sigue igual), pero no cambia nombres, tipos ni
etiquetas JSON.

## Persistencia (`internal/almacen`)

`monitor.yaml` se queda con lo del sistema (`servidor`, `go2rtc`, `salud`). Lo que se edita desde
el panel vive en el **directorio de datos** (`datos:` en monitor.yaml; default
`/var/lib/monitor`; en Windows `%APPDATA%\monitor-camaras`), en JSON, escrito de forma atómica
(archivo temporal + rename) con permisos 0600:

- `sucursales.json` — lista de sucursales. Cada una como en ARQUITECTURA.md más:
  `huella: { mac, serie, modelo, marca, actualizada }` (puede faltar).
- `ajustes.json` — `interfaz` (rotación, vista general, volver a cuadrícula) y `alertas.telegram`.
- `admin.json` — `passwordHash` (bcrypt, `golang.org/x/crypto/bcrypt`) y `vinculos`:
  `[{ id, nombre, tokenHash (sha256), creado, ultimoUso }]`.

Migración: si `sucursales.json` no existe y `monitor.yaml` trae `sucursales`/`interfaz`/`alertas`,
se importan una vez. A partir de ahí manda el JSON. `monitor.yaml` sin sucursales es válido
(la central arranca vacía y se llena desde el panel).

Recarga en caliente: cualquier cambio de sucursales o ajustes regenera `go2rtc.yaml`, reinicia
go2rtc (no el monitor), actualiza la vigilancia de salud y sube `configVersion`.

## API

Todas las respuestas son JSON. Errores: `{ "error": "mensaje en español para mostrar" }` con
código 400/401/403/404/409/500. Las contraseñas de los DVR **nunca** salen en una respuesta:
en lectura vienen como `"password": ""` y `"tienePassword": true`; al actualizar, `password: ""`
significa "no cambiar".

### Pública (sin cambios + 1 campo)

- `GET /config.json`, `GET /api/estado` como en v1. `/api/estado` agrega `"configVersion": n`
  (entero que sube con cada cambio). La tele recarga `/config.json` cuando cambia.

### Panel de administración — modo central

Sesión: cookie `monitor_sesion` (HttpOnly, SameSite=Strict, 12 h). Todas las rutas
`/api/admin/*` salvo `inicio`, `configurar` y `login` exigen sesión → 401 sin ella.
Login con límite: 5 intentos fallidos por IP → bloqueo de 5 min (429).

| Método y ruta | Cuerpo | Respuesta |
|---|---|---|
| `GET /api/admin/inicio` | — | `{ configurado: bool, sesion: bool }` |
| `POST /api/admin/configurar` | `{ password }` (≥ 8) | crea la contraseña; solo si no está configurado (409 si ya). Abre sesión |
| `POST /api/admin/login` | `{ password }` | abre sesión |
| `POST /api/admin/logout` | — | cierra sesión |
| `GET /api/admin/sucursales` | — | `[Sucursal]` con `huella` y estado de salud incluido (`enLinea`, `error`) |
| `POST /api/admin/sucursales` | `Sucursal` | crea; 409 si el id existe |
| `PUT /api/admin/sucursales/{id}` | `Sucursal` | reemplaza (password "" = conservar) |
| `DELETE /api/admin/sucursales/{id}` | — | borra |
| `POST /api/admin/sucursales/{id}/identificar` | — | consulta el DVR ahora; guarda la huella; `{ identidad, advertencias }` |
| `POST /api/admin/sucursales/{id}/reiniciar` | — | reinicia el DVR por su API; 501 si la marca no lo permite |
| `GET /api/admin/ajustes` | — | `{ interfaz, telegram: { chatId, tieneToken } }` |
| `PUT /api/admin/ajustes` | `{ interfaz, telegram: { token?, chatId } }` | guarda (token "" = conservar) |
| `POST /api/admin/telegram/prueba` | — | manda "✅ Prueba del monitor de cámaras" |
| `GET /api/admin/vinculos` | — | `[{ id, nombre, creado, ultimoUso }]` |
| `POST /api/admin/vinculos` | `{ nombre }` | `{ id, nombre, token }` — el token se muestra **una sola vez** |
| `DELETE /api/admin/vinculos/{id}` | — | revoca |

Forma de `Sucursal` en la API (camelCase). `puerto` es el del video (RTSP 554, XMEye 34567) y
`puertoWeb` el de la API HTTP del DVR (80; 8899 en XMEye); 0 = el de la marca.

```json
{
  "id": "centro",
  "nombre": "Sucursal Centro",
  "dvr": { "marca": "dahua", "host": "192.168.2.108", "puerto": 0, "puertoWeb": 0, "usuario": "admin",
           "password": "", "tienePassword": true, "rutaSub": "", "rutaPrincipal": "" },
  "camaras": [ { "canal": 1, "nombre": "Entrada", "clave": true } ],
  "huella": { "marca": "dahua", "modelo": "XVR5104", "serie": "7A0...", "mac": "aa:bb:...", "actualizada": "..." },
  "enLinea": true,
  "error": ""
}
```

### Alta desde el asistente — modo central

| Método y ruta | Auth | Cuerpo | Respuesta |
|---|---|---|---|
| `GET /api/vinculo/comprobar` | `Authorization: Bearer <token>` | — | `{ ok: true, central: "nombre del equipo" }` |
| `PUT /api/vinculo/sucursales/{id}` | Bearer | `Sucursal` (con `password` real) | crea o reemplaza; `{ ok, sucursal }` |
| `GET /api/vinculo/sucursales` | Bearer | — | `[{ id, nombre, dvr: { host } }]` (para avisar de rangos repetidos) |

### Asistente — modo instalador (solo en la laptop, escucha en 127.0.0.1)

Sin sesión (solo local). En modo central estas rutas dan 404, y en modo instalador las de
`/api/admin` y `/api/vinculo` dan 404.

| Método y ruta | Cuerpo | Respuesta |
|---|---|---|
| `GET /api/instalador/redes` | — | `{ redes: ["192.168.1.0/24"] }` (de `descubrir.RedesLocales`) |
| `POST /api/instalador/buscar` | `{ redes?: [] }` | inicia barrido; `{ id }` |
| `GET /api/instalador/buscar/{id}` | — | `{ terminado, hechos, total, hallazgos: [Hallazgo] }` |
| `POST /api/instalador/identificar` | `{ host, marca, puerto?, puertoWeb?, usuario, password }` | `{ identidad, advertencias: [Advertencia] }`; 401 con `ErrCredenciales` |
| `GET /api/instalador/foto?host=&marca=&puerto=&puertoWeb=&usuario=&canal=` + cabecera `X-DVR-Password` | — | `image/jpeg` |
| `GET /api/instalador/central` | — | `{ url, vinculado: bool, nombre }` (guardado en el directorio de datos de la laptop) |
| `PUT /api/instalador/central` | `{ url, token }` | prueba con `/api/vinculo/comprobar` y guarda |
| `GET /api/instalador/sucursales-central` | — | lo de `/api/vinculo/sucursales` |
| `POST /api/instalador/enviar` | `Sucursal` con password | `PUT` a la central; `{ ok }` o error claro |
| `POST /api/instalador/exportar` | `Sucursal` | descarga `sucursal-<id>.json` (por si no hay internet) |

`Advertencia`: `{ nivel: "aviso" | "error", codigo, mensaje }`. Códigos:
`h265` (por canal: "La cámara 3 manda H.265; cámbiala a H.264 en el DVR"), `dhcp` ("El DVR toma su
IP del módem: fíjala"), `sin_rtsp`, `canal_sin_senal`, `rango_repetido` ("La Sucursal Norte ya
usa 192.168.1.x"), `resolucion_alta` (substream > 704×576). El mensaje incluye el paso a paso
corto para esa marca cuando aplica.

## Recuperación por huella (modo central)

Si una sucursal lleva caída `salud.recuperar_tras_minutos` (default 3) y tiene `huella.mac` o
`huella.serie`:

1. Barre su /24 a través de Tailscale con `descubrir.Buscar` (sin ONVIF multicast).
2. A cada hallazgo con puertos de la misma marca le llama `dvr.Nuevo(...).Identificar` con las
   credenciales guardadas (host cambiado).
3. Si coincide la MAC o la serie: guarda el host nuevo, recarga y avisa
   "📍 Sucursal Centro: el DVR cambió de 192.168.1.64 a 192.168.1.112".
4. Máximo un barrido cada 10 min por sucursal. Nunca toca otras redes.

## Interfaz (web)

- `/` — tele. Además: recarga `/config.json` cuando `configVersion` cambia. Si no hay sucursales:
  pantalla "Sin sucursales todavía. Agrégalas desde el panel: http://<host>/admin".
- `/admin` — primera vez: crear contraseña. Luego login. Pantallas: **Sucursales** (lista con estado,
  botón agregar, editar nombre/cámaras/credenciales, identificar, reiniciar DVR con confirmación,
  borrar con confirmación), **Ajustes** (rotación, Telegram con botón de prueba), **Vínculos**
  (crear → muestra el token una vez con botón copiar; revocar).
- `/instalar` — asistente de 5 pasos: **1 Central** (URL + token, o "sin conexión, solo exportar"),
  **2 Buscar** (barra de progreso, lista de hallazgos, "agregar a mano"), **3 Acceso** (usuario y
  contraseña, identificar), **4 Revisión y vista previa** (advertencias + fotos de cada canal
  refrescando cada 2 s, nombres editables, marcar clave), **5 Enviar** (id y nombre de sucursal,
  enviar o exportar, y la comprobación final).
- Textos para personas que no son técnicas: nada de "DHCP" sin explicarlo.

## Modo instalador y app de escritorio

`monitor instalador` levanta el servidor en `127.0.0.1:<puerto libre>` en modo instalador y abre
el navegador en `/instalar`. Después (fase D) se empaqueta como app de escritorio para Windows
con ventana propia; el modo instalador no depende de go2rtc.
